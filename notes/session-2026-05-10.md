# bkgrnd — iOS + WOPR Streaming + Playlist Sync

## Problem
- Build an iOS client for bkgrnd that can play audio on-phone (background + AirPlay) while keeping playlists in sync with a backend.
- Keep the existing macOS menubar app behavior unchanged while adding fault-tolerant playlist sync.
- Provide a simple WOPR backend that can both store playlists and serve a stable streaming URL for iOS playback.

## Solution
- Implemented macOS best-effort playlist YAML sync to WOPR with a local cache under `~/.bkgrnd/`.
- Added a minimal server (`server/`) with playlist endpoints, search, and a `yt-dlp`-backed audio proxy endpoint supporting basic HTTP Range passthrough.
- Added an iOS SwiftUI app source set matching the approved mock (Recent Mixes grid, Now Playing, Search) with background audio plumbing.

## Impact
- iPhone can play bkgrnd streams directly (including background playback and AirPlay) without depending on the macOS app being present.
- Playlists stay reasonably consistent across macOS and iOS via WOPR, but macOS continues working if WOPR is unreachable.
- WOPR becomes the single integration point for YouTube extraction (`yt-dlp`) and stream delivery to clients.
- ✅ Verification: `cargo check` (macOS + WOPR), `npm run build -- --bundles app` (macOS bundle), GitHub Actions “iOS IPA (AltStore)” workflow fixed and producing an artifact.
